**How it is measured.** For each UTC day, `measures.FirstCommitToProductionDay` takes the population pull requests that merged that day. For each one that deployed, and whose first commit time Dispatch knows, it takes the minutes from the first commit to the deploy. The first commit time is the author date of the pull request's first commit, as GitHub reports it. The deploy is the completion of the production job of the first deploy run, created after the merge, that applies the pull request (`delivery.ContainingRun`). `measures.FoldLeadTime` merges the minutes of every day in a window. It answers their count, median, 90th percentile and maximum (`measures.Quantile`), and never the mean of the daily medians.

A population pull request is a merged pull request that the delivery measures count (`delivery.IsPopulationPR`): its author is a population author, its repository is not an excluded one, and it is not a task pull request of the deploy repository. It counts for the project of the issue it names, or else for the project of its repository.

**What it does not count.** Pull requests that have not deployed, pull requests with no known first commit time, and pull requests outside the population.
