**How it is measured.** Each deploy and each failed change of a project is a row of `production_events`, the record of deploys and failed changes. A failure row blames one deploy. It comes from a failure source that the project turned on in its delivery settings: a `fail` result of an `after_merge` check (`check_results`), a merged revert (`reverts`), an issue labelled `incident` that links a pull request or a run (`incident_label`), or a failure that a system posts (`events`). A person's flag in a deploy's drill-down counts whenever any source is on. For each UTC day, `measures.ChangeFailRateDay` builds one share, `per_deploy`: the deploys that finished that day with at least one counted failure, over every deploy that finished that day. A failure counts on the day its deploy finished. A deploy with two failures counts once. `measures.FoldChangeFailRate` adds up the numerators and the denominators of a window's days and divides the sums. It never takes the mean of the daily shares.

A deploy counts for the projects of the issues that its pull requests name. When it ships a pull request that names no issue, it also counts for each other project whose default repository is the deploy's repository. A deploy that ships no pull request counts for the project whose deploy source found it. A posted deploy counts for the project of its route, and only when that project holds an `events` deploy source. A failure counts for each project its deploy counts for whose failure sources include the failure's signal.

**From which day.** The project's `failures_measured_since` is the first day. A window that starts before it reads "no data" and names that day. From that day, a window with deploys and no failure reads 0 percent.

**What it does not count.** A rejected failure: a person or the project's controller rejected it with a reason, which the row keeps. A failure whose signal is from a source the project did not turn on. A deploy that the GitHub adapter dropped, because a rule change no longer calls its run a deploy, and the failures on it. A `bug` label, which makes no failure.
