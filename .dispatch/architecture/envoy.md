The Go-based event transport: webhook ingress, NATS routing and delivery, the native Dispatch server, and the MCP bridge. Dispatch's database is PostgreSQL 18 with pgvector: `envoy-infra`'s `gcp:Dispatch` defaults a new instance to `POSTGRES_18`, and `internal/testpg`, `scripts/dev-postgres.sh` and `deploy/compose/dispatch.acceptance.compose.yml` pin one pgvector-on-18 image by digest. Dispatch packages no child component claims sit here directly, among them the embedding queue (`internal/dispatch/embedqueue`) that keeps meaning search's vectors current, an issue's from its title and its spec. Its NATS hub comes in two forms, both deployed by `envoy-infra` (`packages/envoy/infra`, a Go module of its own that builds a Pulumi plugin and the `envoy-infra` command, and compiles only `daemonpermissions`, `internal/bus` and `internal/contracts` from Envoy): `gcp:NatsHub`, one nats-server on a Google Cloud VM that joins the tailnet, and `gcp:ClusteredNatsHub`, three nats-server pods on a GKE cluster whose optional Tailscale Service hosts forward the tailnet's connections to NATS and to a session listener the component runs as a workload of its own. Both render their NATS users through the one function in `packages/envoy/infra/gcp/natshub.go`, from the permission sets `packages/envoy/infra/core` builds.

The address Pulumi downloads the `envoy-infra` plugin from is stamped in at build time, from the repository the release ran in: `release-envoy-infra.yaml` derives it with `.github/scripts/repo-paths.sh plugin_download_url` and builds the plugin with `-ldflags -X 'github.com/sjawhar/envoy/infra/provider.downloadURL=<that URL>'`, so the schema the plugin serves points at the releases of whatever repository published it, and the job's smoke test compares `pluginDownloadURL` against the same derived value rather than a literal. That is why `provider.go` holds `downloadURL` as a `var` and no longer a `const` — `-X` writes a variable and never a constant — with today's `https://github.com/cybermonklabs/legion/releases/download/envoy-infra-v${VERSION}` as its default, which a build carrying no such flag, a developer's and the package's own tests', serves unchanged; the `${VERSION}` in it is Pulumi's placeholder, filled in at install, and nothing on the way through may expand it.

The secrets broker sits here too (`cmd/broker`, `internal/broker`), and with it this repository's one Go client of its RFC 8693 token exchange: `internal/brokerclient`, re-exported as `packages/envoy/brokerclient` so a module outside this one can import it past Go's internal-package rule, which is how `packages/daemon`'s `legion controller start` proves, before it starts the controller, that this machine can trade for the Dispatch credential the controller's session then holds. A machine trades the Google identity token `internal/googleidentity` reads from its metadata server for a DPoP-bound access token and the launcher credential the same trade mints, under which it enrols its session; that credential is keyed by the machine and the thumbprint of the key its proof presented, so a copy of the identity token asks for a credential of its own rather than moving the machine's, and the session it enrolled renews only while that credential is live — revoked, past its hour, or its account dropped from `BROKER_VM_SERVICES`, and the session lapses within one lease. A person signs in on that machine with `agent-secrets login`, whose device grant gives their own identity token, traded with the machine's as the actor token and recorded as a `person_signins` row keyed by the person, the box key and the machine; their sessions are not held to the machine's login and end when the sign-in is revoked. The Go client and the TypeScript one (`packages/broker-client`) are held to one wire by the corpus at `internal/brokerclient/testdata/wire.json`, which both suites replay. `scripts/dev-stack.sh` boots the stand-in issuer (`cmd/dev-oidc-issuer`), the broker, NATS, the listener and Dispatch together, so the whole path can be driven on one machine with no Google and no cluster.

Two packages here sit outside `internal/` so that the daemon's module can import them. `agentloop` is the one shared model loop (`Run` for a bounded run of a model and its tools, `Decide` for one System One decision call). `packages/daemon/internal/sharedloop`'s test compiles it into the daemon's module, so it stays importable there. Its `Result.Status` carries the HTTP status of a provider error, so a caller can tell a refused request (a 400) from a failure to serve. `going` is the command bar's answer and holds no store and no route. `Answerer.Run` makes the answer call through `agentloop.Run`, paced by the deployment's tokens-per-minute quota before each attempt. It asks first for the strict `Final` object (`answer`, `block`, `arguments`: every property required, no union), and streams the growth of the `answer` property through the filter. The filter escapes the text, passes on a link only as the `item` frame of a thing the model was given, and cuts the answer at 120 words. A service that refuses that request with a 400, or a reply that does not fit the schema before any of its answer reached the reader, is asked the same again for prose, which has no block and no arguments. After a 400 the process asks for prose alone until it restarts (`Answerer.Blocks`). `decide.go` holds the three questions of the decision call and the state it asks them about. `reads.go` holds the read tools an answer may call (`read_roster`, `read_progress`, `read_architecture`, `read_project_activity` and `read_delivery`, eight reads a run at most). `blocks.go` holds the seven block kinds, the words that ask for each kind, and the fill of a block from a read's rows. `record.go` reads `decision_models.json`, embedded in the binary: one entry for each measured model, with its action threshold and its chart-display threshold, each null where its fit does not hold. `cmd/going-bakeoff` writes that record. It puts every case of `going/bakeoff/cases.json`, whose subjects are all made up, to each named model through the questions and the catalogue the server uses, fits the two thresholds (`fit.go`), and names the chosen model. `scripts/going-smoke.sh` boots the real `envoy-dispatch` binary against a fake https model and checks the capability read and one streamed answer.
