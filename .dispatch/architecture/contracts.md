The language-neutral source of truth for event envelopes, subjects, the Dispatch API types (among them `SearchAsk`, the answer state a search hit for an ask carries), and the Dispatch specs the `dispatch` command is built from. `packages/envoy/internal/contracts` is the Go package `bun run gen:go` writes from it; `cmd/listener`, `internal/bus`, `internal/cistore`, `internal/session`, `internal/store`, `internal/mcpbridge` and `internal/dispatch/outbox` import that package directly, so it belongs to this component even though it sits inside `packages/envoy`.

It holds the related-item check's result types (`Suggestions` with its outcome and search mode, `SearchAsk`, `DecisionBlockCheck`, `RelatedChecksReport`) and the `dispatch_related` spec, which runs the check on a text without writing anything. `Suggestions` has no `decision` field, and `WriteSuggestion` no `answered_by` and no `answered_at`. It holds the items of the project the check searched (`related`) and, for a write that asks a person a question, `other_projects`. That field holds at most two answered question asks of other projects, and each item names in its owner the project it belongs to. `RelatedChecksReport` carries `other_project_offers` too, the writes of a window that offered such a question. The `dispatch_related` spec's description tells an agent what the tool lists, and it claims no past decision.

It also holds the refusal codes the server and every client must spell alike, among them `DISPATCH_SIGN_IN_REQUIRED` (`SIGN_IN_REQUIRED`), the `403` for a write by an access token the secrets broker issued that names a session and a service but no person: `bun run gen:go` writes it into the Go package as `contracts.DispatchSignInRequired`, as it does `DISPATCH_LOGIN_CHANGED`, so the server's refusal and a client's reading of it cannot drift apart.

Its `fixtures/daemon-api/` goldens are the daemon's own state answer, written by `packages/daemon/internal/api`'s golden test: `settings.repository_renames` is among them, the `{from, to}` pairs a deployment tells the daemon to treat as one repository, `[]` when it configures none. `src/legion-api.ts`'s `legionSettings` stays loose, so a new settings key needs no schema change.

`src/legion-api.ts`'s `legionIssue` is a `z.strictObject`, so the state's memory fields are mirrored there: `memoryGroup` (`memory` or `none`), `memoryDrawMode` (`off`, `on` or `random`) and `memoryDrawnAt`, each optional and absent together while nothing has drawn for the issue's tree (daemon API contract 49). The `memory` block a project's settings carry needs no schema change, since `legionSettings` stays loose, and the `fixtures/daemon-api/` goldens carry both.

`dispatch_artifact` takes a `precondition` of its own, the document token alone, built by `uploadPreconditionArgument` in `src/dispatch-tools.ts`, apart from `dispatch_doc_edit`'s `preconditionArgument`, which also takes `blocks`: an upload rewrites the whole tree, so only the document token says which version it replaces, and the server refuses a `blocks` guard on one `400 INVALID_PRECONDITION`. `CreateArtifactOptions.precondition` carries it to the upload route as `UploadPrecondition`. `EditPreconditionCurrent.version` is the live version number a `409 PRECONDITION_FAILED` carries where its caller read that number beside the write it refused, which an upload's does and an edit's does not. `WriteAdvice.standing_review` is the review a question's issue already carries on its specification, set only on a question opened on an issue: who reviewed, when, whether they approved or asked for changes, the version the review is pinned to, the first 500 characters of their reason, and whether Dispatch carried the review forward and from which version.
