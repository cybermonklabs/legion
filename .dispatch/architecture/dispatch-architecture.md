The importer that reads `.dispatch/architecture/*.md` from a project's source repository, validates the file set whole (`notes.Parse` — one error naming every problem, so an invalid set is refused and the previous model stays up), and projects it into immutable snapshots and the components tables. A push of a source's branch drives it: the delivery intake (`dispatch-delivery`) hands each push event of a branch to `Importer.Pushed`, which imports every enabled source on that repository (matched whatever its case) and that branch (matched exactly) without waiting for the import, through one push worker per source that looks again until no push is newer than its last import's head lookup, so the pushes that arrive while an import runs, after its head lookup, start one more import between them, and a push that arrives before an import's head lookup is covered by that import and starts none. A manual sync route is the impatient path, and a five-minute ticker (`duty.RunJittered`: each wait at most five minutes and more than four and a half, drawn afresh every time; lease `architecture-import`, whose period is four and a half minutes, `duty.LeasePeriod`) is the repair where a push event never arrives. Within one process, the callers of one source — one project's one repository — share one sync (`singleflight`), so two Refresh clicks cost one set of GitHub calls, and no lock is held across a GitHub call, so a slow source holds up no other source, of its project or of any other. What orders the writes of every process is the source row: each write takes the row's lock and commits only while the row's version (`xmin`) is still the one its sync loaded before fetching. The rules of one note set are a pure leaf package beneath the importer, `internal/dispatch/architecture/notes`, with no database and no network: which entries of the directory are notes (`IsNote`), the 1 MiB bound on one note (`CheckSize`) and `Parse`; the importer calls `notes.Parse`, and `githubapp`'s `Dir` and `DirFiles` (`dispatch-auth`) call the note rule and the bound, so the importer reaches those two through its GitHub reads. The command `cmd/architecture-check` runs the same package over a checkout's notes directory, and the composite action `.github/actions/architecture-check` builds that command and runs it in any repository's CI, so a repository's CI judges its notes by the rules the importer applies to them.
