The Delivery page's record of pull requests, workflow runs and deploys, kept from GitHub two ways. The intakes consume GitHub notifications from NATS on durable consumers (one binder per durable, the other process standing by): `Intake` checks each message's subject before decoding anything, and runs pull requests and workflow runs at once up to the consumer's `MaxAckPending`, in delivery order per pull request or run; `StopDelivering` hands its queued messages back to NATS for the next holder. `Intake` also hands each push of a branch to the architecture importer, with no delivery settings and as no delivery fact, so a component source is imported when its branch moves; it reaches the importer through `PushImports`, an interface this package declares, so the package imports no `architecture` package (`cmd/dispatch` passes the importer to `StartIntakes`). Both intakes route by one `SettingsCache`, read at start and again when `delivery_settings_changed` notifies `dispatch_delivery_settings` (migration 0156). The reconcile (`Reconcile.Run`) is a five-minute timer loop (`duty.RunJittered`, lease `delivery-reconcile`) that catches up what no webhook delivered, since GitHub has no feed of what was missed; `measures` computes the DORA and pipeline figures from the stored rows. It reaches NATS through the listener's bus client (`envoy-listener`), GitHub through the App client (`dispatch-auth`), and decodes envelopes with the generated Go contracts (`contracts`).
