The Delivery page's record of pull requests, workflow runs and deploys, kept from GitHub two ways. The intakes consume GitHub notifications from NATS on durable consumers (one binder per durable, the other process standing by): `Intake` checks each message's subject before decoding anything, and runs pull requests and workflow runs at once up to the consumer's `MaxAckPending`, in delivery order per pull request or run; `StopDelivering` hands its queued messages back to NATS for the next holder. `Intake` also hands each push of a branch to the architecture importer, while delivery settings are saved (it runs only then) and as no delivery fact, so a component source is imported when its branch moves; it reaches the importer through `PushImports`, an interface this package declares, so the package imports no `architecture` package (`cmd/dispatch` passes the importer to `StartIntakes`). Both intakes route by one `SettingsCache`, read at start and again when `delivery_settings_changed` notifies `dispatch_delivery_settings` (migration 0156). The reconcile (`Reconcile.Run`) is a five-minute timer loop (`duty.RunJittered`, lease `delivery-reconcile`) that catches up what no webhook delivered, since GitHub has no feed of what was missed; `measures` computes the DORA and pipeline figures from the stored rows. It reaches NATS through the listener's bus client (`envoy-listener`), GitHub through the App client (`dispatch-auth`), and decodes envelopes with the generated Go contracts (`contracts`).

Two evals of the registry (`dispatch-evals`), code survival at 30 days and post-merge rework at 30 days, are measured from GitHub's patches by a daily run, `codesurvival.Run` (`internal/dispatch/codesurvival`), with the computation of this package's children `delivery/survival` and `delivery/survival/fold`.
`survival` imports the standard library alone and reads no tree, no clone and no blame: it parses one commit's patch (`ParseDiff`, `FilesPatch`), replays a branch's first-parent patches in chain order while it follows the lines of the changes it measures (`Replay`), and answers, for each change, the lines it added, those still there at its 30-day mark (its committer time plus 30 days), the later changes that removed the others by then, and the lines that commits which merged no pull request removed (`Measure`).
The run is a leased loop of an hourly tick, the first at start (`duty.RunLeased`, lease `code-survival`, `codesurvival.Tick`), so one process runs each tick, and it starts only where the server holds the GitHub App's private key.
A tick does the daily pass of each repository that is some project's default repository, once a UTC day, and again the same day only after a pass that GitHub's budget or a rate limit stopped, once the time that stop set has passed (`code_repos.retry_at`).
A pass reads the branch's first-parent chain from its tip (`GET /repos/{owner}/{repo}/commits`, walked by `parents[0]`) back to the oldest day it holds a fingerprint of, or the repository's start day, less three days.
It compares each stored day's fingerprint, the count of that day's first-parent commits and the sha256 of their SHAs, with the chain, and marks each measured day that a changed day touches in a transaction of its own before it reads any pull request or patch (`WriteMarks`).
A day waits to be measured from 33 days after its start, 00:00 UTC (`survival.WaitsFrom`): the 30-day mark of its last change falls within 31 days of its start, and two days' grace follow for a commit that reaches the branch after the time it is dated.
A run measures up to 28 days from the oldest marked day, else from the oldest waiting day where at least seven wait, else from the oldest blocked day last tried a week or more before (`survival.SelectDays`), so each change is measured once, after its mark, and its day is measured again only when a force-push marks it.
It reads the merged pull requests of the replay range from the closed pull requests list, matched to the chain by `merge_commit_sha`, and each change's issue as attribution gives it: the one `pull_request_heads` holds where attribution judged the pull request under the current rule, else `Attributor.IssueOf`.
It reads each commit's patch as a diff, a commit of two or more parents through the compare route from its first parent, within 32 MiB and `githubapp.DiffTimeout` (60 s), and reads the commit's `files[]` in place of a diff GitHub refuses; a commit that neither gives whole blocks the days whose 30 days hold it.
Eight workers read the patches, which reach `survival.Measure` one at a time in chain order, and each is released once it is applied.
Before it reads the pull requests it counts the requests the rest of the pass will make, and it stops, storing no result and keeping its marks, where GitHub's remaining budget less that count falls below a quarter of the limit, or falls there while it reads.
One transaction stores the results in five tables (`dispatch-store`) and rebuilds the two evals' day rows of every project the results count for (`evals.WriteCodeDaysTx`), and the outbox is drained after it commits.
It keeps counts and keys alone: each change's lines, pull request, head branch, author login and issue, each pair of a change and a later change that removed its lines, and each replayed day's fingerprint, never a patch, a diff or a list of a branch's commits.
Each tick is one attempt of the `code_survival` GitHub read (`githubreads`), and each repository's pass logs one `codesurvival: run` line.
A save of a project's delivery settings wakes the regroup (`codesurvival.Regroup`, a woken loop with no lease on `dispatch_delivery_settings`), which rebuilds from the stored results the day rows of each project whose code groups moved, with no GitHub request.
