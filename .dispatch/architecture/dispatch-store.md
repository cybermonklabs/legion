The schema every other package reads and writes through: ordered migrations applied in one transaction each at boot, the pool, and the session and people rows — which is why it imports `auth`. `internal/pgmigrate` holds the runner's rules, which the secrets broker's runner shares: the whole migration set is refused before anything applies when two files share a version or a file is misnamed or unreadable, and every migration's lock waits are bounded at five seconds. `internal/pgmigrate` reads migration and census SQL as Postgres 18's lexer does.

The schema also announces the changes the background loops wake on: `embeddings_enqueue` notifies `dispatch_embeddings` when it writes a row (0151), a row trigger on `refs` notifies `dispatch_excerpts_owed` for each document mention left owed an excerpt (0153), `delivery_settings_changed` notifies `dispatch_delivery_settings` for a settings change other than freshness (0156), a row trigger on `document_edit_notices` notifies `dispatch_edit_notices` for each notice given a due time (0157), and every event commit notifies `dispatch_events` (0107). The loops' own state is three additions: `reference_excerpt_backoff` (0152), each failing document's version, failures in a row and next attempt; `suggestion_outcome_cursor` (0154), the one row holding the highest event id the outcome sweep has judged by; and `write_suggestions.swept` (0155), whether a pass has judged a suggestion against all its events, with the partial indexes `write_suggestions_unswept` and `write_suggestions_pending_artifact`. The pool's listener pool dials the held LISTEN connections: the delivery hub's and the event stream relay's, the process's one shared listener, which carries the background loops' wakes and the document rooms' room sync, and the document rooms' NOTIFY sender.

The store also holds what the related-item check reads and writes: each project's term statistics (`search_term_stats`, `search_term_totals`, kept up to date under the `search-term-stats` lease), one `related_checks` row per check, and the trigger that embeds an issue as its title and spec (migrations 0139 and 0140). A pass of that refresh applies what changed rather than counting every item again: triggers on `asks`, `comments`, `issues`, `messages` and `document_search` queue each item whose search text a write changed, with the vector it held before (`search_term_queue`, migrations `20261101182508_search_term_queue` and `20261101182522_search_term_queue_triggers`), and a pass drops exactly the queued rows its own snapshot sees, which it writes beside the counts (`search_term_totals.snapshot`, migration `20261101182515_search_term_totals_snapshot`) so that a later pass can tell its own work from another writer's. It holds the items each check offered too, one `write_suggestions` row per item, and `write_suggestions.role` admits three values since migration `20261111212235_write_suggestions_other_project`: `related`, `decision`, and `other_project`, the role of an answered question of another project. That migration drops the narrower check constraint and adds the wider one in one statement, so no moment passes with the column unchecked, and it rewrites no row. No release after it writes a `decision` row, and the rows written under that role before it stay, because each is the record of what its own check offered. The lease pool has one connection per leased caller, fifteen.

The store holds the command bar's records too. `going_requests` and `going_events` (migration `20261105152945_going_requests`) hold each question and the frames of its answer for an hour. Migration `20261112191507_going_requests_cancelled_at` adds `going_requests.cancelled_at`, which the cancel route sets; after it is set, the API stores no frame of that run that does not end the stream. Migration `20261112173940_going_runs` adds `going_runs`, the run record: one row for each answered pause, under the going request's id and with no foreign key, so the row stays for thirty days after the request's one-hour sweep. A row holds the author's canonical login, the words, the context chip, the hits, the decision, the proposal, the `writes` and `undos` JSON arrays that one statement appends to one element at a time, the issue keys the run touched (`issues`, read through the GIN index `going_runs_issues`), `structured_output`, `created_at`, and `finished_at`, which is null for a run that did not end. `going_runs_author_created` serves a person's runs newest first. Migration `20261112220930_user_going_settings` adds `user_going_settings`, a person's `confirm_writes` keyed by canonical login; a person with no row reads false. Each of the three adds a table or a nullable column and rewrites no row, and its census answers 0.
