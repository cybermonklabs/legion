Stages 1 and 2 on `main` provide Postgres migrations and boot history (`internal/store`), the local daemon registry, durable role claims, and pending task delivery (`internal/registry`). Stage 3 (LEGION-219) plans the per-issue record, admission slots, phase and gate facts, transactional outbox, and `internal/projection`; the coordinator never mirrors Dispatch or GitHub.

The issue record holds no experiment answer of its own: what each unit was drawn for is a row of `experiment_assignments` (migration `20261111045636_experiment_assignments`), keyed by the issue key and the experiment's name, carrying the unit the draw covers (`tree` or `issue`, the two words the loader takes), the arm, the mode in force at the draw, the instant, and the carried mark. The row is written once and never updated, as the draw it records is made once: the primary key is what makes that true in the schema, since both writers insert `on conflict (issue_key, experiment) do nothing`, so an experiment a unit has been running under keeps the arm, the mode and the instant it was drawn with whatever the project's file says by then, and a re-admission, a new generation and `ClearTreeGeneration`, which touch the issue row alone, keep what was drawn. `record.Store.PutAssignments` is the draw's write, made by every path that opens a unit in that path's own transaction, and it selects from the issue's own record: a key the daemon holds no record of — an operator's spawn, whose tree's root it never recorded — writes no row and raises nothing, where the row's cascading foreign key would otherwise fail that admission. `CarryAssignments` is the hand-over's write: every tree-unit row of the tree a child left is copied onto the child with its arm, its mode and its instant verbatim and the carried mark set, so the work goes on running under those arms; then each experiment declared at the hand-over lands at no variant, no mode and no instant under the same write-once insert, so it settles exactly the experiments the copy left unwritten, and the child is drawn for by nothing later. Only the tree rows are copied, an issue row of the old root being that one issue's own answer. The empty variant is the record's way of saying no arm, which the two columns beside it tell apart: an experiment at mode off draws for no unit and records the mode `off` with the instant of the draw, while a settled hand-over records neither. A unit opened before an experiment was declared holds no row for it and runs in no arm of it. The four `issues.memory_*` columns that `20261104073148_issue_memory_group` and `20261104153554_issue_memory_carried` added stay in the schema and are written and read by nothing from this release on; `20261111045636` back-filled every root holding a draw (`memory_drawn_at` not null) or the carried mark into one `memory` row of unit `tree`, so no tree drawn before the deploy lost its exposure, and a later release drops them.
