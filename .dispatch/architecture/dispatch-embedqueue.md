How meaning search's vectors are made and kept. `embed` is the embedder client, Cohere Embed v4 on AWS Bedrock or Azure AI Foundry, whose identity every stored vector records. `embedqueue` embeds what the write triggers enqueue in `embeddings`: a woken loop (`duty.RunWoken`) that scans when `embeddings_enqueue` notifies `dispatch_embeddings` (migration 0151), when the coverage pass writes `embeddings` rows, or when the earliest pending row falls due, at most once per 5 s, claiming its rows so two processes never embed the same one, and never calling the model inside a write's transaction. The coverage pass (`Cover`) runs once at start with no lease: it adds what no trigger saw, repairs stale issue rows and then records each issue's inputs where its row holds its current text (`recordIssueSources`, into `embedding_issue_sources`), and, once the embedder has answered, drops vectors another identity made; the identity steps and the record step run again every 10 minutes (`identityRecheckInterval`) for as long as the process runs, and a pass whose closing report fails logs it at WARN (`dispatch embedqueue: coverage pass report failed`) and fails nothing. `GET /api/v1/search/coverage` reads its counts (`Coverage`) in one statement, so one snapshot, under a 10 s `statement_timeout`, past which it counts nothing and answers `503 SEARCH_COVERAGE_TIMEOUT`; the bound is the server's own because pgx closes the client connection when a caller's context ends and sends Postgres no cancel, so a statement with no bound ran on after its caller left. It reads the window kinds from two partial covering indexes alone (`embeddings_window_embedded`, `embeddings_window_unembedded`), never a window's text, and builds and hashes an issue's text only where the issue's inputs changed since they were recorded.
