The private workspace package both Oh My Pi plugins bundle (`@legion/pi-shared`): the versioned in-process interface the Envoy plugin publishes and the Legion plugin reads, and the modules both entries inline — the role-claim bridge, the injected-user-turn record, the subagent check, the host types, the jj session attribution overlay every harness's pane commits through — with the real-binary test harness and the shared skills-guard and cross-import rules.

`src/approval-message.ts` (`@legion/pi-shared/approval-message`) names the approval message's custom type (`APPROVAL_MESSAGE_TYPE`), which pi-legion places and pi-envoy puts its answers message before. It says which message is the approval message (`isApprovalMessage`) and cuts a request before its trailing run of approval messages (`splitTrailingApproval`). `src/custom-entry.ts` holds the readers of a session's custom entries: every entry of one type (`customEntries`), and the newest one this build can read (`lastCustomEntry`).

`src/context-request.ts` (`@legion/pi-shared/context-request`) holds how both plugins' `context` handlers read one model request. It tells a side turn (`isSideTurn`), the handoff prompt (`isHandoffPrompt`) and a compaction in progress (`sessionCompacting`, read off the live session that `liveAgentSession` finds in the host's `AgentRegistry`) from a request of the conversation's own loop. It says where a request ends on the session's branch (`branchPosition`) and what the request is among its session's conversions (`nextConversion`). `nextConversion` reads the request without the answers messages pi-envoy added after its last message, so both plugins read a request the same way whichever handler runs first. It tells such a message by one predicate that pi-envoy uses too (`isAddedAnswersMessage`): a user message whose first text block is the answers list or its failure line (`isSessionAnswersMessage`), with the stamp that pi-envoy puts on each user message it adds (`ADDED_MESSAGE_TIMESTAMP`, which pi-envoy's `userTextMessage` writes). The module also reads a message's role and timestamp (`roleOf`, `timestampOf`), the key a message is matched by (`messageKey`), and a message's first text (`leadingText`). It cuts a request before a trailing run of messages that match a test (`splitTrailing`), which `splitTrailingApproval` and `nextConversion` both use. A caller passes the host's `AgentRegistry` in, so the module imports host types only and loads where the host package does not resolve, as in each plugin's unit tests.

The daemon client (`src/daemon-client.ts`) reads `POST /legion/v1/claims/approval` as `approval`, under an abort signal the caller passes, so pi-legion's 800 ms deadline leaves no request open. The host types (`src/pi-types.ts`) carry the context's `model`, whose `compat.supportsMidConversationSystem` says whether the model takes a `system` message inside the conversation, and the `before_provider_request` event, whose result replaces the wire body.
