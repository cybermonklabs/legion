# The rules every phase's evidence follows

Read it when you test a change, record the checks after a forward merge, run the simplify pass, or run the reviewer's pair. The `Thermo` line it names is a line of the template in `skill://legion-worker/references/pr-body.md`.

- The tester tries to break the changed surface (wrong and boundary inputs, the second and the concurrent run, the party it must refuse) and writes the red test for a way no test would catch. Lint, types and the unit and integration suites are CI's: read them on GitHub at the head, rerun no lane as evidence, and wait for none.
- A `rejected` `implementerProof.verdict`, or `failed > 0`, always comes with the failure recorded in `failures`.
- After a forward merge, the tester reruns each check the merge can reach (`skill://legion-worker/references/conflicts-and-rewrites.md`) and records each other check with no `ci_check` at the new head unrun, its `--observed` naming the earlier pass and why the merge misses it. A class search that finds an instance, or a parent's last round, takes a full test round.
- The implementer runs `skill://simplify-settled-diff` once per pull request, in its first implementing round, after its own results and before it completes, whatever the diff touches, a docs-only diff included. It is scoped to the pull request's own diff at that head, and the pass covers every file of the diff, workflow YAML and documentation with the code. Applied: rerun the fast local checks (the tests it added or changed, by name, and the build, vet, lint and type checks of the packages it touched) and the issue's checks the simplify diff touches, and record them at the applied head. That cost is why 0-applied is the expected outcome and a pass that applies is spent sparingly. A defect the pass reports is fixed outside the pass and the results recorded again, never dropped as out of scope; the `Thermo` line names the count and the fixing commit.
- The reviewer's pair runs at the head each round reviews, over the diff that round reads, when that diff touches runtime code, that is any file but documentation, workflow and configuration files; the `Thermo` line records the range it read and a row per half, and earlier rounds' rows stay beside them.
