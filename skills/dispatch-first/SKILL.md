# Dispatch first

- Before you plan, file an issue, ask or start work, run `dispatch search --query '<two or three words>'`, and open each hit that can be yours.
- Work already tracked gets your finding on its issue. File a new issue only when no hit covers the work, and cite the nearest one you ruled out.
- A question already decided: cite the answered ask (`dispatch://KEY/ask/<id>`) and never ask again.
- A duplicate: fold it only when it is the same work. Keep the issue with the spec, copy to it what only the duplicate has, and close the duplicate (`--status done --reason 'Duplicate of dispatch://KEY.'`). On a duplicate with the `legion` label or another holder's claim, comment the kept issue's name instead.
- Ask a person only for what their authority, taste or risk appetite settles, and only through Dispatch: a blocker that is not an open ask does not exist for them. A Legion phase worker sends decisions to its architect instead.
- Record each request you accept in Dispatch before you start it. Before you end a turn, each is done, in progress or an open ask.
- Read `skill://dispatch` before your first `dispatch` command, and `skill://dispatch-writing-specs` before you write a spec, ask, comment or message a person reads.
