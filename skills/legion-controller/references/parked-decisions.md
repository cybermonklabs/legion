# Decisions on a parked tree

Read this on a `parked-decision` wake, and for the parked-root walk at every start and on each `tick`. A parked tree is a labelled root in `backlog` or `icebox` whose `issues.<KEY>.phase` is `done`. Its architect is gone, so nobody inside it hears a person's decision. The daemon sends you each one as `parked-decision` (`decision`, `root`, `ref`, `actor`, and a spec decision's `version` and `reason`); the walk finds those sent while no controller ran.

A person's own approval of a parked root's primary document while no tree is live is no decision for you: the daemon sets the root `todo` itself, unless the daemon sends it as a `parked-decision` whose `reason` says the root's status changed after the approval and Legion queued nothing; decide that one as [Deciding](#deciding) says. A carried approval, or one on a root that keeps a Dispatch parent, is a decision. A session's reply on a parked tree is none.

A held root is not a parked one: `todo` on a root at `phase: held` releases the hold at the same generation. A root still in the workflow whose architect stopped takes `backlog`, then `todo`, which re-admits the tree.

## Deciding

1. **Where the tree stands.** Read `issues.<root>`.
   - `phase` is not `done`: the tree runs. When its `architect.state` is `failed` or `retired`, nobody heard: judge it in steps 3 and 4, and re-admit a tree whose decision gives a next step with `backlog`, then `todo`, once the `worker-died` cause is gone (`skill://legion-controller/references/wakes.md`). In those comments write `<root>'s architect has stopped, so it` for `<root> is parked, so its architect` and `The tree waits.` for `The tree stays parked.`. Otherwise the tree heard it: do nothing.
   - `phase` is `done`: `dispatch read --issue <root>`. In `backlog` or `icebox`, go on. In any other status, set nothing and name `ref` in your summary.
2. **Who parked it.** Under the root's `Events:`, each `issue.created`, `issue.updated` and `issue.closed` line ends `status <status>`. The park is the oldest line of the newest unbroken run of those lines showing the current status. It is your own hold only when that line is by `session legion-daemon:<PROJECT>` and, within 10 minutes after it, a session's comment begins `Parked by Legion while it waits on:`. Every other park is someone else's. `Events:` shows only the last 10 events: when the run reaches the oldest one shown, read `/api/v1/issues/<root>/events?limit=200` with the `curl` of `skill://legion-controller/references/session.md` ("Reading Dispatch's API"); when it still does, you cannot read who parked it, so judge only the events newer than the oldest you read, and name older decisions in your summary as ones you could not place. A decision older than the park is no reason to run.
3. **Read once.** A `Parked decision read:` comment from any session, newer than the decision, on the root or the decision's issue, has judged it: do nothing.
4. **Judge the words, not the kind.** Read the decision (`dispatch read --ref <ref>`; for an approval, `issues.<root>.designGate` and `gatedSteps`). An approval and its approval request's `ask.answered` are one decision, `ref` `dispatch://<KEY>/spec`.
   - It gives the work a next step: an approval (every `gatedSteps` entry `approved`; an `approvedVersion` below `currentVersion` counts), a change request that says what to change, an answer that picks an option or supplies the fact, a reply that tells the agent to go on.
     - Your own hold: `set_status` the root to `todo`, and comment `Parked decision read: <ref> by <login> gives this tree its next step (<one sentence>). Legion runs it again.`
     - Another's park, or one you cannot read, whose words ask Legion to start the tree: `todo`, and comment `Parked decision read: <ref> by <login> asks Legion to start this tree. Legion runs it again.`
     - Another's park otherwise: set nothing, and comment `Parked decision read: <ref> by <login> gives this tree its next step (<one sentence>).`, then `<parker> parked the tree, so it stays parked until a person sets it to todo, approves its spec when it has no parent, or asks Legion to start it.` (the login, `session <id>`, or "The tree was parked through Legion (session legion-daemon:<PROJECT>) for no hold of its own"), then, for an ask's answer or reply, `Its architect then starts with this decision.`
   - It only questions the work: leave it parked, and reply `Parked decision read: <ref> by <login> asks <the question in a few words>.`, then the answer and where in the record it is (issue, spec, handoffs, pull request) and `The tree stays parked. Set <root> to todo to run it.`; or, when the record does not answer it, `The record does not answer it, and <root> is parked, so its architect cannot answer either. Set <root> to todo to bring its architect back to answer.` For another's park, end with that park's sentence instead of `Set <root> to todo …`.
   - Post on the issue where the decision was made: under its ask, `dispatch comment --issue <KEY> --reply-to-ask <ask id> --turn human --body-file -`; under a reply, `--reply-to <comment id>`; for a change request, a plain comment on that issue. When that issue is not the root, post a short copy on the root as well. Several decisions on one tree get one comment naming each `ref`.

## The walk

1. List the parked roots: `dispatch issues --project <PROJECT> --status backlog --label legion --all`, then with `--status icebox`. Keep those `read_state` records at `phase: done`.
2. Read each root, then each issue under it, level by level (`dispatch issues --project <PROJECT> --parent <KEY> --all`).
3. A decision is an event by a `user`, newer than the root's park and every `Parked decision read:` comment on its issue, of type `artifact.approved`, `artifact.changes_requested`, `ask.answered`, `ask.resolved` or `comment.created`. Skip an `artifact.approved` that is the person's own handover: the root's `parent` is `null`, the event's `payload.artifact_id` is the root's `primary_artifact_id` (the same `curl` of `/api/v1/issues/<root>`), and its `payload.reason` does not begin `Carried forward from the approval of version`. When that read fails, judge it. Find an ask or comment's id under `Open asks:` or with `dispatch search`; `dispatch read --ref dispatch://<KEY>/ask/<id>` prints its `Ask id:`.
4. Decide each tree's decisions as [Deciding](#deciding) says.
5. For each root that is your own hold and had no decision this walk, check its wait: for an `event:` key, read what its reference names; for any other mark, judge the cause by step 3 of `skill://legion-controller/references/escalation.md#an-escalated-hold` (a missing `capabilities` row proves nothing, since a parked tree runs no session). When the event has happened or the cause is gone, `set_status` the root to `todo` with a comment that cites the mark and what you checked. Otherwise move nothing, and name the root and its wait in your summary.
