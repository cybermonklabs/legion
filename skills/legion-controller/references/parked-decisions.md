# Decisions on a parked tree

A parked tree is a labelled root in `backlog` or `icebox` whose `issues.<KEY>.phase` is `done`. Its architect is gone, so nobody inside it hears a person's decision. The daemon sends you each one as `parked-decision` (`decision`, `root`, `ref`, `actor`, and a spec decision's `version` and `reason`). The walk finds those sent while no controller ran, except a `carried-gate-opened`, whose approval is an event of the root that owns the carried document, outside the parked tree.

A person's own approval of a parked root's primary document while no tree is live is no decision for you: the daemon sets the root `todo` itself. The exception is a `parked-decision` whose `reason` says that the root's status changed after the approval and Legion queued nothing. Decide that one as [Deciding](#deciding) says. A carried approval, or an approval on a root that keeps a Dispatch parent, is a decision. A session's reply on a parked tree is none.

A held root is not a parked one: `todo` on a root at `phase: held` releases the hold.

## Deciding

1. **Where the tree stands.** Read `issues.<root>`.
   - `phase` is not `done`: the tree runs. When its `architect.state` is `failed` or `retired`, nobody heard the decision. Judge it in steps 3 and 4, and say in your comment that its architect has stopped, not that the tree is parked. Restart a tree whose decision gives a next step (`backlog`, then `todo`) once the `worker-died` cause is gone (`skill://legion-controller/references/wakes.md#worker-died-architect`). Otherwise the tree heard it: do nothing.
   - `phase` is `done`: `dispatch read --issue <root>`. In `backlog` or `icebox`, go on. In any other status, set nothing and name `ref` in your summary.
2. **Who parked it.** In `dispatch read --issue <root> --all-events`, each `issue.created`, `issue.updated` and `issue.closed` line ends `status <status>` (a forced create adds `· forced …` after it). The park is the oldest line of the newest unbroken run of those lines that show the current status. It is your own hold only when that line is by `session legion-daemon:<PROJECT>` and, within 10 minutes after it, a session's comment begins `Parked by Legion while it waits on:`. Every other park is someone else's. A decision older than the park is no reason to run.
3. **Read once.** A `Parked decision read:` comment from any session, newer than the decision, on the root or on the decision's issue, has judged it: do nothing.
4. **Judge the words, not the kind.** Read the decision (`dispatch read --ref <ref>`, and for an approval `issues.<root>.designGate` and `gatedSteps`). An approval and its approval request's `ask.answered` are one decision, and `ref` is the approved document's.
   - It gives the work a next step: an approval (every `gatedSteps` entry `approved`, where an `approvedVersion` below `currentVersion` counts), a change request that says what to change, an answer that picks an option or supplies the fact, or a reply that tells the agent to go on.
     - Your own hold, or another's park whose words ask Legion to start the tree: `set_status` the root to `todo`. Say that Legion runs the tree again.
     - Another's park otherwise: set nothing. Name who parked it, and say that the tree stays parked until a person sets the root to `todo`, approves its spec when it has no parent, or asks Legion to start it.
   - It only questions the work: leave the tree parked. Give the answer and where the record holds it (issue, spec, handoffs, pull request). When the record does not answer it, say so, and say that `todo` on the root brings its architect back to answer.
   - Begin the comment `Parked decision read: <ref> by <login>`, then say what the decision gives and what you did. Post it where the decision was made: under its ask (`dispatch comment --issue <KEY> --reply-to-ask <ask id> --turn human --body-file -`), under a reply (`--reply-to <comment id>`), or as a plain comment for a change request. When that issue is not the root, post a short copy on the root as well. Several decisions on one tree get one comment that names each `ref`.

## The walk

1. List the parked roots: `dispatch issues --project <PROJECT> --status backlog --label legion --all`, then the same with `--status icebox`. Keep those that `read_state` records at `phase: done`.
2. Read each root, then each issue under it, level by level (`dispatch issues --project <PROJECT> --parent <KEY> --all`). Read each issue's events with `dispatch api --path '/api/v1/issues/<KEY>/events?limit=200'`, and the next page with `&after=<the last event's seq>` while a page holds 200.
3. A decision is an event by a `user`, newer than the root's park and than every `Parked decision read:` comment on its issue, of type `artifact.approved`, `artifact.changes_requested`, `ask.answered`, `ask.resolved` or `comment.created`. Skip an `artifact.approved` that is the person's own handover: the root's `parent` is `null`, the event's `payload.artifact_id` is the root's `primary_artifact_id` (`dispatch api --path '/api/v1/issues/<root>'`), and its `payload.reason` does not begin `Carried forward from the approval of version`. When that read fails, judge the event.
4. Decide each tree's decisions as [Deciding](#deciding) says.
5. For each root of your own hold that had no decision this walk, check its wait. For an `event:` key, read what its reference names. For any other mark, judge the cause by step 3 of `skill://legion-controller/references/escalation.md#an-escalated-hold`. A missing `capabilities` row proves nothing, because a parked tree runs no session. When the event has happened or the cause is gone, `set_status` the root to `todo` with a comment that cites the mark and what you checked. Otherwise move nothing, and name the root and its wait in your summary.
