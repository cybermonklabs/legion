Each mode declares what it needs in one table, which `--help` prints and the mode checks before it reads or judges anything: the tools on `PATH` (`git`, `curl`, `jq`, `python3`, `uv`, `go`, `bun` and the `dispatch` command, each where its mode runs it), the packages `bun install --frozen-lockfile` writes for `--landed`'s committed proof, the history `--shape` and `--landed` read, the clone root, and `DISPATCH_URL` and `DISPATCH_TOKEN_FILE`, the Dispatch token this pod already holds. It clones what it needs under `$TMPDIR/ioc-clones`, one commit deep and with no tags, which is the clone the triage read.
The gate reads GitHub through `git` and the REST API and never through `gh`, which in a Legion pod is scoped to this project's owners alone: a repository's files from a clone at pinned commits, and what only the REST API answers, a pull request's reviews, times and size, with `curl`. No recorded command and no script a row runs calls `gh`, and `--admitted` refuses a row that does.
`--replay` also needs a `git` credential helper that answers for `theorem-labs/agent-infra`, a private repository, as a Legion pod's `legion git-credential` does: rows read it at pinned commits, most from a blobless clone `env.sh` fetches under `$IOC_CLONES/agent-infra` at the commits `sources.json` pins, and a few its pull requests through the REST API. `--replay` reads the repository with `git ls-remote` before the GitHub budget and before `env.sh` builds anything, and a reader whose `git` cannot read it gets `--replay` ending cannot-run naming it and the rows that read it, exit 2, and no `FAIL`.
A recorded read of GitHub's REST API, and `env.sh`'s read of the review corpus, send the token the machine's credential helper gives through `git credential fill` for the repository read, from a header file `--replay` writes under its own scratch, readable by its owner alone, and passes to `curl` as `-H @<file>`; with no token they read unauthenticated, held to GitHub's sixty requests an hour. An installation token lives an hour and a replay takes longer, so `--replay` writes the files again from a fresh `git credential fill` before a row once they are ten minutes old.
No line the gate prints and no output a row records holds the token, and the files go with the run's scratch however the run ends.
When a row's read of a live source fails, only the source's answer about the record fails the row: every row's `curl` of GitHub's REST API or of the Dispatch API runs with `--fail-with-body`, and the gate reads the same address once more with the same header file and names the status and the message; a row's `dispatch` command is read by the first line it printed, and a row's `python3` that reads `DISPATCH_URL` by the last `urllib` error its output holds.
A read that got no answer, a server error (5xx), a rate limit, or an answer about the reader's credential (a 401, or a 403 for a permission or a token, so that an expired token never reads as a wrong deliverable) ends the mode cannot-run, naming the row, the source and the line that shows it, with no `FAIL`; any other answer, such as a 404 or Dispatch's `NOT_FOUND`, fails the row.
Every tool cache, `env.sh`'s own and a recorded command's, go's module and build caches among them, is under `IOC_CACHE` by one table in `env.sh`, which `--help` prints, and each recorded command runs with an empty `TMPDIR` of its own, so a fresh `IOC_CACHE` replays as a machine that never ran it; where the gate writes, what a tool still writes outside both roots, the rule that a predicate reads the measured line rather than a tool's progress, the pinned-read rule, that a row reading a live node is held to a fact fixed in time and never to the node's present state, with a predicate that can still fail as the node moves on, and that a script whose output this tree commits, as `coordination/count.py` is, reads each live source as it stood at a fixed instant, the rule that a row's predicate holds every part its claim names, the rule that nothing a killed run leaves under `IOC_CACHE` or `IOC_CLONES` is reused, and the environment each fixture of `--self-test` runs in, are stated once, in `check.sh`'s header.
